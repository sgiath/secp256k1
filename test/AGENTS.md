- Do not edit `vectors/*.csv` or `vectors/*.json` casually. Treat them as upstream snapshots; update `vectors/README.md` provenance (commit-pinned URL and source SHA256) if replacing them.
- Do not weaken vector expectations to fit implementation behavior.
- Do not remove subprocess tests around formerly aborting MuSig probes; they protect BEAM crash boundaries.
- Subprocess probes must reach native code: call `Secp256k1.NIF.*` directly with the malformed term. `Secp256k1.MuSig` guards raise `FunctionClauseError` before the NIF runs.
- Tag slow tests (child BEAM subprocesses) `@tag :expensive`. Plain `mix test` excludes them; `mix check` runs them via `mix test --include expensive`.
- Do not inline DER/vector parsing into individual tests. Keep shared parsing in `support/` (`support/vectors.ex` loads JSON vectors with Jason, a dev/test dependency, because Elixir's built-in `JSON` needs 1.18 and the minimum is 1.16).
- Vector tests exercise only the public API. BIP-327 `sign_verify`, `tweak`, and `sig_agg` vectors run in `secp256k1/musig_vectors_test.exs`; `nonce_gen` and `det_sign` vectors are not bundled because they need injected randomness or raw secret nonces. `vectors/README.md` lists skipped and adapted cases.
- Vector tests fail when a fixture shrinks: they pin the 463 Wycheproof cases (and check the fixture's `numberOfTests`), the 19 BIP-340 rows with exactly 8 signing and 8 public-key checks, and per-category BIP-327 counts. A skipped BIP-327 case must be listed in the `@excluded` manifest of `secp256k1/musig_vectors_test.exs` by category, index, and comment, matching `vectors/README.md`; unknown error categories fail.
- `support/musig_subprocess.ex` `run(setup, probe)` puts every `ebin` of the current `Mix.Project.build_path/0` on the child's code path, prints `MUSIG_SUBPROCESS_PROBE` between setup and probe, and kills a child still running after 15 s, returning `{output, :timeout}`. Crash-boundary tests assert the probe marker directly precedes `MUSIG_SUBPROCESS_ARGUMENT_ERROR`, so a setup failure cannot satisfy them.
- Shared MuSig signing helpers (`signers/1`, `session_for/3`, `sign_with/3,4`) live in `support/musig_flow.ex`. Assert positive MuSig and Schnorr verifications with `== true`.
- Property tests live in `secp256k1/property_test.exs` (StreamData/ExUnitProperties, a dev/test dependency) and replay from the ExUnit seed. Keep expensive properties at a small `max_runs`.
- Fault-injection tests (`secp256k1/native_fault_test.exs`) are tagged `:fault_injection`; `test_helper.exs` excludes the tag unless the loaded NIF was built with `SECP256K1_NIF_FAULT_INJECTION=1` (it probes `Secp256k1.NIF.fault_live_resources/0`). Do not also tag them `:expensive`: `--include expensive` would override the exclusion in normal builds. `NIF.fault_call(fail_at, name, args)` runs the guarded NIF `name` with its `fail_at`th fault point failing (`0`: none), returns or raises its result, and sends `{:secp256k1_fault, hits, net_allocs, failed_point}` to the caller. Iterate `fail_at` from 1 until `failed_point` is `nil`; every run must have `net_allocs == 0`. Child BEAMs read `SECP256K1_NIF_FAULT_LOAD` to fail a load fault point; name `Secp256k1.NIF` only as data in the probe, because compiling a remote call loads the NIF before the setup runs.
